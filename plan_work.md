# uni-git — план работ

Собственный кросс-платформенный Git-клиент: простой, с интеграциями для Unity. Главный критерий: мгновенный запуск. Второй: функции, которых не хватает в Fork.
Референс интерфейса: Fork (без его верхней панели).

---

## 1. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Приоритет №1 | Время от клика до окна. Ориентир: ≤ 250 мс тёплый старт |
| Языки | Только C++ / Python / JS / TS. Rust и Go исключены |
| Платформы | Windows и macOS обязательно с первой версии. Linux потом, не критично |
| Зависимости в рантайме | Установленный Node.js допустим. Упаковка Python/Node в бинарник — нет |
| Оболочка | **Neutralinojs** (готовое C++-ядро ~2.5 МБ + системный webview: WebView2 на Windows, WKWebView на macOS) |
| Бэкенд | Node.js + TypeScript, отдельный процесс, поднимает локальный HTTP/WebSocket-сервер на 127.0.0.1 |
| Фронтенд | TypeScript + HTML/CSS, ходит к бэкенду напрямую по HTTP/WS (не через шину Neutralino), поэтому отлаживается в обычном Chrome |
| Работа с git | Вызов `git` CLI (как в Fork), без libgit2. Все нужные операции — одна-две команды |
| Аутентификация | Поверх Git Credential Manager (входит в Git for Windows, есть на macOS): OAuth GitHub/GitLab/Bitbucket/Azure, PAT, SSH-ключи |
| Rebase | Не нужен. Только merge. Cherry-pick нужен |
| Резидентный режим / трей | Нет |
| Хранение настроек, шаблонов задач | Локально у пользователя (не в репозитории) |
| Кнопка «актуализировать мастером» | Рядом галочка **stash**: прятать незакоммиченное перед операцией и возвращать после |
| Дерево префабов Unity | Показывать и для конфликтов, и для обычного диффа в стейдже |
| Название, репозиторий | **uni-git** (было epic-git), github.com/roflseech/uni-git, публичный |
| Распространение | Установщик одной строкой из GitHub Releases: `irm …/install.ps1 \| iex` (Windows), `curl -fsSL …/install.sh \| sh` (macOS). Ставит недостающее (Git+GCM, Node, WebView2) и приложение в папку пользователя без прав администратора |
| Обновления | Каждый push в `main` — релиз (GitHub Actions, бесплатно для публичного репозитория). Приложение обновляется само: бэкенд проверяет при старте, ставит в фоне, полоска «Restart now / Later», не диалог. Свой апдейтер в бэкенде, не `Neutralino.updater` (тот переписывает только `resources.neu`, бэкенд не трогает, ничего не проверяет). Релизы подписаны ed25519 |

### Результаты замеров (прототипы, тёплый старт, эта машина)

| Технология | Медиана до видимого окна |
|---|---|
| Python + Tkinter | 118 мс |
| Python + DearPyGui | 176 мс |
| Python + PySide6 | 220 мс |
| **Neutralino** | **228 мс** |
| Electron | 258 мс |
| Python + pywebview | 607 мс |

Прототипы удалены после выбора стека. Найденные особенности Neutralino (учтены в `app/` и `frontend/src/main.ts`):
- ищет `resources.neu` по argv[0]/cwd; путь с прямыми слэшами ломает поиск и молча показывает встроенную заглушку;
- размер окна задаётся в физических пикселях, на HiDPI масштабировать через `devicePixelRatio`;
- `window.*`, `filesystem.*`, `os.*` должны быть в `nativeAllowList`;
- закрытие: сначала `window.hide()`, потом `app.exit()`, иначе окно висит ~300 мс, пока сворачивается WebView2;
- бинарник не подписан. Установка скриптом этого не замечает: файлы, скачанные `Invoke-WebRequest`/`curl`, не получают пометку «из интернета» (Windows) и карантин (macOS), поэтому SmartScreen и Gatekeeper молчат; на Apple Silicon бинарник подписывается локально ad-hoc (`codesign -s -`). Настоящая подпись понадобится, только если раздавать zip через браузер;
- расширения (extensions): handshake-JSON (`nlPort`, `nlConnectToken`, `nlExtensionId`) приходит в stdin **без перевода строки**; на Windows расширение запускается через `cmd.exe /c`, поэтому родитель бэкенда — cmd.exe; при принудительном убийстве оболочки её WebSocket к расширению закрывается не сразу, поэтому бэкенд следит за PID оболочки (`NL_PID`, фронт передаёт его при подключении) и выходит в пределах ~250 мс. Для dev-режима есть флаг `--enable-extensions=false` (`neu run -- --enable-extensions=false`);
- stdout расширения оболочка глотает — бэкенд пишет `data/logs/backend.log`.

## 2. Архитектура

```
┌──────────────────────────────────────────────────────────┐
│ Neutralino shell (bin)     окно, трей-нет, диалоги ОС     │
│   └─ WebView2 / WKWebView                                │
│        └─ frontend (TS)  ──HTTP/WS──►  backend (Node+TS) │
│                                          ├ git CLI       │
│                                          ├ очередь задач │
│                                          ├ fs-вотчеры    │
│                                          ├ Unity YAML    │
│                                          └ OAuth/askpass │
└──────────────────────────────────────────────────────────┘
```

Принципы:
1. **Окно сразу, данные потом.** Оболочка и Node стартуют параллельно. UI рисуется с кэшем последнего состояния репозитория, затем обновляется.
2. **Ни одной модалки на git-операции.** Каждая операция — задача в очереди конкретного репозитория с прогрессом, логом и отменой.
3. **Блокировка на уровне репозитория.** Пока в репозитории идёт задача, действия над ним недоступны (кнопки disabled), но можно переключиться на другой репозиторий и работать там. Задачи разных репозиториев идут параллельно.
4. **Git никогда не ждёт ввода в терминале.** `GIT_TERMINAL_PROMPT=0`, свой `GIT_ASKPASS` и `SSH_ASKPASS`: запрос пароля/подтверждения хоста приходит в UI как событие.
5. **Бэкенд без состояния UI.** Всё, что знает бэкенд, можно перезапросить; падение бэкенда = перезапуск процесса, окно остаётся.

Хранение — **portable**: всё лежит в папке `data/` рядом с приложением (`<папка uni-git>/data/`). В репозитории пользователя ничего не пишется, кроме штатных git-настроек через `git config` (имя, email, mergetool, `.gitattributes` для Unity по явному согласию).
- `data/config.json` — группы и репозитории, глобальные настройки;
- `data/repos/<id>.json` — настройки репозитория: main-ветка, шаблон задач, auth-профиль (имя/email живут в `.git/config` самого репозитория, мы их только показываем и меняем);
- `data/cache/<id>/` — последнее состояние для мгновенного показа;
- `data/logs/` — логи операций.
На macOS, если приложение лежит в `/Applications` и папка недоступна для записи, `data/` создаётся в `~/Library/Application Support/uni-git/` с тем же форматом.

Установленная копия (`install.ps1` / `install.sh`): Windows — `%LOCALAPPDATA%\Programs\uni-git\` (ярлык в меню «Пуск»), macOS — `~/Library/Application Support/uni-git/app/` плюс запускатель `~/Applications/uni-git.app` (скрипт `exec ./uni-git-mac_* --path=<папка>`: само приложение вне бандла, чтобы обновлять его без пересборки бандла). `data/` лежит рядом с приложением, апдейтер его не трогает; заменённые обновлением файлы ждут следующего старта в `.update/`.

## 3. Интерфейс (по макету и скринам Fork)

### Верхняя панель
| Элемент | Поведение |
|---|---|
| **Repositories** | Дропдаун: список групп; внутри группы — репозитории; кнопки «Add group», «Add repo» (открыть локальную папку / клонировать по URL). Текущий репозиторий подсвечен. Устройство групп — см. «Группы и репозитории» ниже |
| **Repo Settings** | Локальные `user.name` / `user.email` (показывать откуда взяты: local/global), группа репозитория, main-ветка (по умолчанию `master`/`main` автоопределение), аутентификация (профиль GCM/SSH), **шаблон задач** (см. «Интеграция с задачами») |
| **Global Settings** | Путь к git, путь к UnityYAMLMerge, команда редактора (по умолчанию VS Code), тема, библиотека пресетов шаблонов задач |
| **Open in Code** | Открывает текущий репозиторий в VS Code (`code <путь>`; на macOS при отсутствии CLI — `open -a "Visual Studio Code" <путь>`). Рядом в дропдауне: «Open group in Code» — доступно, если группа привязана к папке |
| **Merge** | Меню из трёх пунктов, см. ниже |
| Fetch / Pull / Push / Commit | Обычные операции, Commit ведёт в экран Changes |
| **Статус-бар операций** | Сверху, показывает: «⟳ clm-client: pull…», «⟳ other-repo: fetch…». Клик — лог операции, кнопка отмены |

### Меню Merge (main = ветка из настроек репозитория)
| Пункт | Что делает |
|---|---|
| **Merge main** | `git merge <main>` в текущую ветку (локальный main как есть) |
| **Force merge actual main** | [stash если галочка] → `git fetch origin <main>:<main>` (локальный main догоняет remote без переключения) → `git merge <main>` → [stash pop]. Это «проактуализировать мастером» |
| **Merge into main** | [stash если галочка] → `git switch <main>` → `git pull` → `git merge <текущая>` → **`git push` автоматически** → остаёмся на main. Если merge дал конфликт, push не выполняется, UI переходит в Conflicts |

При конфликте операция завершается в состоянии merge, UI переходит в Changes с секцией Conflicts.

### Группы и репозитории
Группа бывает двух видов, и оба могут сосуществовать в одном списке:

| Вид | Как создаётся | Что содержит | Open group in Code |
|---|---|---|---|
| **Группа-папка** | «Add group → From folder»: выбираешь корневую папку | Все git-репозитории внутри папки находятся автоматически. **Глубина строго 1**: `Root/Repo1` попадает, `Root/Repo1/Repo2` — нет. Список обновляется кнопкой «Rescan» и при старте. Лишние можно скрыть | Да — открывает корневую папку группы |
| **Ручная группа** | «Add group → Empty» | Репозитории добавляются по одному из любого места: «Add repo → Open folder / Clone» | Нет (нет общей папки) |

Дополнительно:
- В группу-папку тоже можно добавить репозиторий вручную из другого места. Он помечается как «внешний» и в «Open group in Code» не попадает.
- Один и тот же репозиторий может быть только в одной группе.
- Клонирование в группу-папку по умолчанию предлагает её корень как место назначения.
- Пример: рабочая папка `D:\Work` с пятью репозиториями → одна группа-папка. Личный репозиторий из `D:\Dev\misc\` (где рядом лежат ещё двадцать чужих) → ручная группа «Personal» с одним репозиторием.

### Интеграция с задачами (Repo Settings → Task template)
Шаблон задаётся **на репозиторий**; можно выбрать «без шаблона». Никаких имён веток по умолчанию нет: если шаблона нет, поле «создать ветку» — обычное текстовое поле.

Поля шаблона:

| Поле | Назначение | Плейсхолдеры |
|---|---|---|
| Регэксп кода задачи | Распознавать код в именах веток и коммитах | — |
| Шаблон имени ветки | Как собрать ветку из введённых полей | `{type}`, `{name}`, `{code}` |
| Список типов веток | Значения для `{type}` (например `feature`, `fix`); если пусто — поле типа не показывается | — |
| Шаблон сообщения коммита | Как оформить коммит; пусто = коммит без пометок | `{code}`, `{message}` |
| Шаблон ссылки | Ссылка в трекер | `{code}` |

Два пресета из коробки (их можно править и сохранять свои):

| | Пресет «Jira» | Пресет «ClickUp» |
|---|---|---|
| Регэксп кода | `[A-Z]+-\d+` | `[0-9a-z]{9}` |
| Ветка | `{type}/{name}#{code}` → `feature/new-gang-grades#OST-52990` | `{code}_{name}` → `869eu8fkw_fish-weight` |
| Типы | `feature`, `fix` | — |
| Коммит | пусто — без опознавательных знаков | `[{code}] {message}` |
| Ссылка | `https://chillgamingg.atlassian.net/browse/{code}` | `https://app.clickup.com/t/3862640/{code}` (id команды вшит в шаблон) |

Поведение в UI:
- **Создать ветку**: диалог с полями по шаблону — тип (выпадающий, если задан), название, код задачи в отдельном поле. Предпросмотр итогового имени.
- **Коммит**: если у текущей ветки по шаблону распознан код и задан шаблон коммита, subject автоматически получает префикс (`[869eu8fkw] `), его можно убрать вручную. Кнопка «вставить код задачи» рядом с полем.
- **Ссылка на задачу**: кнопка/иконка возле имени текущей ветки и возле коммитов, где распознан код; клик открывает трекер в браузере. Коды в сообщениях коммитов кликабельны.
- Распознавание кода из ветки идёт по регэкспу, а не по шаблону, поэтому работает и для веток, созданных руками или коллегами.

### Дифф
Свой встроенный просмотрщик с первой версии, **только просмотр, без редактирования**: подсветка синтаксиса, side-by-side и inline, свёрнутые неизменённые блоки, stage/unstage по ханкам. Внешний diff/merge-инструмент не планируется; для конфликтов — take ours/theirs и UnityYAMLMerge.

### Левая панель
- Переключатель центрального окна: **Changes** (со счётчиком локальных изменений) / **Commits**.
- Поле фильтра.
- Дерево: **Branches** (группировка по префиксу `feature/`, `fix/`…, текущая отмечена ✓, счётчик ahead/behind), **Remotes**, **Tags**, **Stashes**, **Submodules**.
- Контекстные меню веток: checkout (для удалённой — создать локальную и отслеживать, **в фоне**), merge into current, cherry-pick последнего коммита, delete, «содержит ли коммит…», «вмерджена ли в…».

### Центр: Changes
- **Unstaged** и **Staged** — деревья файлов с кнопками Stage / Unstage, stage по клику на файл, по папке, всё сразу.
- **Conflicts** — отдельная секция во время merge/cherry-pick: для каждого файла «take ours / take theirs / открыть мерж-тул / отметить решённым». Для `.prefab`/`.unity`/`.asset` — дерево объектов (см. Unity ниже).
- Справа — дифф выбранного файла с подсветкой синтаксиса, переключение side-by-side / inline, стейджинг по ханкам.
- Внизу — Commit subject, Description, галочка Amend, кнопка Commit (+ Commit & Push). Кнопка «вставить код задачи» по шаблону.

### Центр: Commits
- **Одна линия — только текущая ветка** (без графа всех веток, как в Fork). Столбцы: бейджи refs (локальные/удалённые ветки, теги, HEAD), сообщение, автор, короткий hash, дата.
- Фильтр коммитов: по тексту сообщения, по автору, «только мои». Быстрый — по загруженному списку, глубокий — `git log --grep --author`.
- Панель деталей: автор, email, дата, SHA, родители, полное сообщение, список файлов (дерево/плоский), дифф файла.
- Контекстное меню коммита: cherry-pick в текущую, создать ветку/тег, копировать SHA, «в каких ветках есть этот коммит».
- Ленивая подгрузка истории при прокрутке.

## 4. Полный список функций

### Базовый git-клиент
- [ ] Открыть локальный репозиторий, клонировать по URL (с прогрессом)
- [ ] Группы двух видов: группа-папка с автопоиском репозиториев и ручная группа; переключение, запоминание последнего
- [ ] Open in Code для репозитория и для группы-папки, команда редактора настраивается
- [ ] Статус рабочей копии, stage/unstage файлов, папок, ханков
- [ ] Commit, amend, commit & push
- [ ] Fetch, pull, push (с установкой upstream), force push с подтверждением
- [ ] Ветки: список, создать, переключить (в т. ч. удалённую — асинхронно), удалить, переименовать
- [ ] Merge (три сценария выше), разрешение конфликтов, abort merge
- [ ] Cherry-pick (одного коммита и диапазона), abort
- [ ] Stash: создать (с сообщением), применить, pop, удалить, просмотр содержимого
- [ ] Теги: список, создать, удалить, push
- [ ] Remotes: список, добавить, удалить
- [ ] Submodules: список, init/update
- [ ] История текущей ветки, детали коммита, дифф
- [ ] Фильтр коммитов по тексту и автору
- [ ] Discard changes файла/папки, ignore файла (правка .gitignore)
- [ ] Просмотр и изменение локальных `user.name` / `user.email`, профили «работа/личное»

### Вопросы про ветки одной кнопкой
- [ ] «Есть ли коммит X в ветке Y» — `git merge-base --is-ancestor X Y` / `git branch --contains X`
- [ ] «Вмерджена ли ветка A в B» — `git merge-base --is-ancestor A B` / `git branch --merged B`
- [ ] Ahead/behind текущей ветки относительно main и upstream — всегда на виду

### Асинхронность и статус
- [ ] Очередь задач на репозиторий, параллельность между репозиториями
- [ ] Статус-бар фоновых операций с логом и отменой
- [ ] Блокировка действий над занятым репозиторием, при этом свободное переключение на другой
- [ ] Askpass через UI (пароль, passphrase SSH-ключа, подтверждение неизвестного хоста)
- [ ] Вотчеры файловой системы с debounce → автообновление статуса

### Аутентификация
- [ ] Вход через браузер (OAuth) для GitHub / GitLab / Bitbucket / Azure DevOps через Git Credential Manager
- [ ] Personal Access Token для любого хоста
- [ ] SSH: показать ключи, сгенерировать, скопировать публичный, проверить соединение
- [ ] Экран учёток: какие хосты залогинены, выйти
- [ ] Проверка наличия GCM и подсказка по установке

### Unity
- [ ] Автонастройка `.gitattributes` и mergetool для `.unity`, `.prefab`, `.asset` под UnityYAMLMerge
- [ ] Поиск UnityYAMLMerge по `ProjectSettings/ProjectVersion.txt` и папкам Unity Hub, ручной путь в настройках
- [ ] Парсер Unity YAML (документы `--- !u!<class> &<fileID>`, `stripped`, PrefabInstance modifications)
- [ ] Дерево объектов: GameObject → компоненты, вложенность по Transform, имена скриптов по guid из `.meta`
- [ ] Дифф префаба/сцены в стейдже как дерево с бейджами изменённых объектов и списком свойств «было → стало»
- [ ] Конфликты: три стороны из индекса (`:1:`, `:2:`, `:3:`), классификация по свойству (только у нас / только у них / одинаково / конфликт), текст «Player → Transform → localPosition.x: база 0, у нас 1.5, у них 2.0»

Сделано:
  - выделение (файл, коммит, ветка) переставляет класс на строке без пересборки; списки пересобираются только когда изменилось их содержимое (status сравнивается без `at`, как refs; из jobs вид берёт только «занят» и текст баннера; тулбар не перерисовывается на события прогресса); при пересборке сохраняется прокрутка;
  - двойной клик: `watchDoubleClicks`/`onRowDoubleClick` в `dom.ts` — по второму `mousedown` (`detail`, чётные значения, ключ строки), на контейнере, переживающем пересборку; быстрые двойные клики по строкам подряд срабатывают все. Выделение строк — по нажатию, а не по отпусканию;
  - **stage/unstage оптимистичные**: файлы сразу переезжают между списками локально (`App.moveLocally`), выделение едет за файлом, дифф не перерисовывается; настоящий статус приходит по окончании задачи (пока тихая задача в очереди, обновления статуса пропускаются, чтобы не откатить показанное). Тихие задачи не блокируют интерфейс (`repoBusy` считает только не-quiet): бэкенд всё равно исполняет задачи репозитория по очереди;
  - Commits: правая колонка собрана из частей (мета, файлы, заголовок диффа, дифф), каждая перерисовывается отдельно; при выборе другого коммита/файла старое содержимое остаётся до прихода нового (приглушается, если загрузка дольше ~0,2 с) — без мигания «Loading…»; фоновое обновление лога не трогает список, если первая страница не изменилась (подгруженные страницы и прокрутка сохраняются), детали коммита не перезапрашиваются (коммит неизменяем, обновляется только «In branches»).
  - Попутно: задача «stage …commit…» больше не очищает форму коммита; ответ HTTP на мутацию не затирает более свежее состояние задачи из WebSocket.

- **Апдейтер** (`backend/src/updater.ts`, без зависимостей: `fetch` + `crypto`): выключен для `-dev`-версий, без `resources.neu` рядом (не установленная копия), в папке только для чтения и при `UNI_GIT_NO_UPDATE`.
